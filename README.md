# Tab Grove · 网页整理

一个本地运行的 Chrome Manifest V3 扩展，按网站主域名整理网页，支持新网页自动归组和悬浮小助手。

## 安装（不需要构建）

1. 打开 Chrome，在地址栏输入 `chrome://extensions`。
2. 开启右上角「开发者模式」。
3. 下载并解压本仓库（GitHub 页面点击 **Code → Download ZIP**），或使用 Git 克隆仓库。
4. 点击「加载已解压的扩展程序」，选择包含 `manifest.json` 的项目目录。
5. 在 Chrome 工具栏的扩展菜单里找到 **Tab Grove · 网页整理**，可将它固定到工具栏。
6. 点击扩展图标，打开快捷弹窗；点击弹窗底部「打开完整管理页面」，再进入独立的管理网页。

## 两种页面

- **快捷弹窗**：点击 Chrome 工具栏的扩展图标后出现，不会自动新开标签页。使用固定的 370 × 560 像素外框，长内容只在内部滚动，避免弹窗自动测量尺寸时抖动。可选择当前窗口或全部窗口，显示对应的标签页、网站和重复网址数量；点击「一键按域名分组」，确认范围后批量整理。与完整管理页共用同一后台整理逻辑，跳过固定标签页和内部页面，应用已记住的 label。也可快速切换自动归组和悬浮助手。
- **完整管理页面**：点击弹窗底部「打开完整管理页面」，查看和搜索所有标签页、批量整理、管理网站规则，以及进行精细设置。当前窗口已打开管理页面时直接切换过去，避免重复开页。也可以从 Chrome 扩展的「选项」入口打开。

弹窗与管理页面共用本机保存的设置。Chrome 在点击弹窗外部时会自动收起弹窗，后台自动归组仍可继续运行。

### 从旧版更新

在 `chrome://extensions` 找到 Tab Grove，点击该扩展卡片的刷新按钮。新版本为显示悬浮助手增加了普通网页访问权限，Chrome 如提示权限变更，需要允许后才能显示助手。刷新已有网页以加载小叶；Chrome 设置页、扩展管理页和扩展商店等受限页面不能显示悬浮助手。

旧标签组可以在整理面板点击一次「一键按域名分组」，合并同站子域名并统一使用简短名称。

## 使用

- 左侧按网站浏览标签页，名称显示为 `X`、`BILIBILI`、`GITHUB`，鼠标悬停可查看完整主域名；搜索框可匹配标题与完整网址，按 `/` 快速聚焦。
- 点击网页标题，切换到原网页和它所在的窗口。
- 默认只显示当前窗口，也可以选择全部窗口。设置保存在本机。
- 「一键按域名分组」对当前筛选结果操作；「整理此网站」仅整理该网站。操作前会显示数量及影响。
- 生成的是 Chrome 原生标签组。批量整理会按完整网址顺序加入标签组；每个窗口分别处理，不会跨窗口搬动网页。
- 手动批量整理会应用已记住的网站规则；没有规则时按网站名称分组。所选网页可能离开原有的自定义组。此版本没有撤销分组按钮。
- 固定标签页、Chrome 内部页面、本地文件跳过分组。没有自动关闭或批量关闭行为。
- 「重复网址」显示所有完整网址相同的网页，包括应保留的一份；参数、锚点、协议不同不视为重复。点击单个 `×` 关闭，Chrome 的 `Ctrl+Shift+T` 可重新打开刚关闭的标签页。
- `search.bilibili.com`、`www.bilibili.com`、`bilibili.com` 视为同一网站。通过随扩展打包的 Public Suffix List 识别主域名，包括 `co.uk`、`com.cn` 等后缀。独立托管站点（如 `alice.github.io` 与 `bob.github.io`）保持独立。显示名称相同但主域名不同的站点也不会自动合并。
- 标签页新增、关闭、移动和网址更新会自动反映到整理页面。

## 新网页自动归组

默认开启，可在左下角「整理偏好」关闭。不需要一直打开整理面板。新标签获得网址、完成加载或跳转后，会复用当前窗口的对应组，没有则创建。系统没有扫描并立即改动所有旧标签的启动操作；已有网页可手动批量整理。

命中已保存规则的网页按规则优先级归组；没有匹配规则时，手动选择的自定义组仍会保留，从自动组手动移出的标签页在本次浏览器会话中不会被反复加回。自动归组仅处理普通浏览器窗口中的 HTTP/HTTPS 页面，跳过固定标签页。拖动标签页时 Chrome 暂时拒绝编辑的错误会显示在偏好设置中，可手动重试。

## 四级分组规则

规则优先级由高到低为：

| 优先级 | 范围 | 示例 | 匹配方式 |
| --- | --- | --- | --- |
| 4 | 具体网页 | https://x.com/1234/lalala | 完整网址，区分协议、路径、参数与 # 片段 |
| 3 | 域名前缀 | api.x.com、search.api-dance.com | 完整主机名精确匹配，忽略协议和端口，不包含更深层子域名 |
| 2 | 根域名 | x.com、api-dance.com → 社交 | 包含根域名下的子域名；旧版网站规则自动兼容 |
| 1 | 默认 | x.com → X | 没有自定义规则时，按根域名自动分组 |

同一网页命中多条规则时，只采用最高优先级规则。新开页面、页面跳转和一键整理共用这一规则。不同网站可以使用同一个 label；不同窗口仍分别建立标签组。

在完整管理页勾选网页，点击「设置分组规则」，选择根域名、域名前缀或具体网页，再选择已有 label 名称或输入新名称。保存后立即按优先级整理选中的网页，并为后续页面保存规则。相同匹配范围与地址再次保存会更新原规则；低优先级规则不会覆盖更具体的规则。

点击「查看全部规则」可按优先级查看匹配地址、目标 label，修改名称或移除规则。修改或移除后，新页面使用更新后的规则；已有网页可通过一键整理重新应用。选择过的网页若已跳转、固定或关闭，保存前会要求刷新列表。

## 小叶悬浮助手

- 普通网页上显示一只小猫，点击展开、拖动换位置。位置会保存在本机，并随窗口大小调整。
- 先选择根域名、域名前缀或具体网页范围，面板会显示将保存的匹配地址和当前生效的规则。
- 从列表选择当前窗口的已有 label，点击「加入」，保存规则并整理当前网页。
- 输入名称并选择颜色，点击「创建」，保存规则并整理当前网页；已有同名 label 时复用。若已有更具体的规则，面板会说明当前网页实际加入的组。
- 可以收起助手、在本页暂时隐藏，或在整理偏好中关闭所有网页的助手。

新页面自动归组由「新网页自动归组」开关控制；保存规则不会擅自打开该开关。关闭自动归组时，手动保存和一键整理仍然会应用规则。

## 本地界面预览与测试

需要 Node.js 22 或更新版本。扩展运行本身不需要 Node.js；域名解析库已打包在 `vendor/`，运行时不访问 CDN，也无需安装依赖。

```powershell
npm.cmd test
npm.cmd run preview
```

完整管理页面预览地址为 `http://127.0.0.1:4173`；快捷弹窗预览为 `http://127.0.0.1:4173/popup.html`。预览使用明确标注的示例数据。真实标签管理和原生工具栏弹窗必须加载 Chrome 扩展；普通网页无权读取 Chrome 标签页。

预览的小叶使用示例 label，操作不会更改真实标签页。核心、事件队列、归组规则通过 Node 测试和 Chrome API 模拟验证；真实 Chrome 的权限及内容脚本加载需安装后检查。

开发时若更新域名解析库：`npm.cmd ci` 后运行 `npm.cmd run vendor`。依赖版本锁定在 `package-lock.json`；第三方许可保留在 `vendor/tldts.LICENSE`。

## 权限与隐私

申请 `tabs`（读取网址、标题并管理标签页）、`tabGroups`（创建和命名原生标签组）、`storage`（保存偏好、位置及网站规则）、`scripting` 和 HTTP/HTTPS 网页访问权限（在普通网页显示小叶）。悬浮界面使用 Shadow DOM 隔离样式。无服务器、统计脚本、外部字体或图标请求；代码不收集网页正文、不上传网址。

API 参考：[Chrome Tabs](https://developer.chrome.com/docs/extensions/reference/api/tabs)、[Chrome Tab Groups](https://developer.chrome.com/docs/extensions/reference/api/tabGroups)。

主域名解析：[tldts](https://github.com/remusao/tldts)。
